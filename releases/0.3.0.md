- Support canonical team and role transfer sources into private recipient namespaces. Verify and retain shared partition requirements through notes-only and nested handoffs.
- Expose inherited requirements on retrieval candidates and enforce them through the engine authorizer for recall, export, claim confirmation, approval and application.
- Add export audience projection for copied episodes and dependent records. Refuse copied episodes with invalid source fingerprints.
- Verify notes-only retention separately from recall eligibility. Suppressed, expired and revoked copies remain unavailable for recall but support reviewed erasure when their live package and sealed certificate match. Missing legal-hold metadata, changed or missing packages, and active holds still block deletion.
- Preserve existing native JSON shapes and source fingerprints when no shared restrictions exist. No new database schema migration is required.
- Add sealed correction ancestry with exact contributor fingerprints, inherited shared restrictions and bounded depth. Both stores verify it for retrieval, nested transfers and retention; current source suppression, expiry, revocation and holds remain effective. Native and transfer fingerprints retain their existing formats when correction evidence is absent. Host human-review authorization and atomic receipts remain required; the platform shared-correction write guard is still retained pending full workflow verification.
- Hosts using raw storage APIs must recheck current recipient and reviewer membership. Deploy synchronized platform, broker and library versions before enabling shared-source transfers.
